# 🎬 TTD Guard

![LICENSE](https://img.shields.io/badge/LICENSE-MIT-blueviolet?style=for-the-badge)
![PYTHON](https://img.shields.io/badge/PYTHON-3.11-blue?style=for-the-badge)
![DOCKER](https://img.shields.io/badge/DOCKER-READY-blue?style=for-the-badge)

### 一句话：把 NAS 影视库里「重复的、画质差的、缺集的」片子自动找出来，确认后清理掉，给 115 网盘腾空间。

> 如果你的环境是 **Emby + CloudDrive2 挂载 115 网盘 + STRM 刮削**，
> 而且库里同时躺着「自己整理的本地库」和「转存来的分享库」两套资源——这个工具就是给你写的。

---

## 你是否有这些困扰？

| 困扰 | TTD Guard 的做法 |
|---|---|
| 同一部电影存了两份，一份在本地库（占 115 空间）、一份在分享库，不知道该留哪份 | 自动逐片比画质，按你的策略保留更优的那份 |
| 分享库那版画质更好，可本地那份还在白占网盘空间 | 确认后删本地 STRM，并**联动删除 115 上的对应源文件** |
| 某季剧集缺了 E01，或中间被和谐断了几集，留在库里碍眼 | 自动识别「残次品」，本地 / 分享各自独立判定，谁不完整删谁 |
| 洗版删除 STRM 时附属文件删除失败，留下可确认的字幕 / nfo 残留 | 「洗版残留」页面一键扫描 + 全选删除 |
| 追的新剧还没入完，就被当成「缺集 / 落后」误判处理 | 入库静默期：15 分钟内变动过的标题自动跳过，不入治理队列 |
| 想知道某部剧 TMDB 上更新了没、自己缺哪几集 | 追更订阅 + 缺集检查，结果可推送到 Telegram |
| 懒得开电脑，想用手机看一眼状态、顺手执行一次治理 | Telegram Bot 远程查看与执行（受保护） |

## 它是怎么工作的（30 秒看懂）

1. **扫描** —— 同时遍历「本地库」和「分享库」两个 STRM 目录，按 TMDB ID / 标题把同一部影视配对。
2. **决策** —— 比画质、比完整度，按你选的策略算出每一部该留哪份、删哪份。
3. **出清单** —— 生成一份「治理计划」，逐条写明**删什么、为什么删**。⚠️ **这一步不动任何文件。**
4. **执行** —— 你看完清单、点击确认，它才真正删除。

> ### ⚠️ 安全第一（请务必读完）
>
> **默认流程永远是：先扫描 → 再生成计划 → 最后由你手动确认执行。工具不会自动删除任何东西。**
>
> 即使开启了「定时巡检」，也**只扫描并推送通知，不会自动清理**。
>
> **删除是不可逆的**：STRM 与云端源文件都是直接删除，工具不保留副本、不提供回收站。
>
> 因此**强烈建议第一次部署只做预览**，确认清单符合预期后，再执行清理。

## 一个例子

以《某某剧》第二季为例，两库都有：

**情况 A —— 分享库画质更好、且完整**

- 本地库：1080P，E01–E10 完整
- 分享库：2160P HDR，E01–E10 完整

→ 清单显示「《某某剧》S02：分享画质达标 10/10 集 → 删本地腾网盘」
→ 本地那份被删除（并联动删掉 115 源文件），Emby 里继续正常播放分享库那份。

**情况 B —— 分享库画质好但缺集**

- 本地库：1080P，E01–E10 完整
- 分享库：2160P，**缺 E05**（中间断层，疑似被和谐）

→ 分享库那份判定为「残次品」被清理，本地 1080P 完整版保留。
→ **宁要完整，不要残缺**：不会因为画质更高就留下缺集的版本。

## 核心功能

- **双库治理**：对比本地库与分享库的电影 / 剧集，按画质与完整度生成治理计划。
- **逐集择优**：剧集逐集对齐后按达标率择优，分享画质更优则删本地（联动删 115 源文件腾空间），本地更优则淘汰分享。
- **残次品清理**：前序缺失（缺 E01）、中间断层（疑似被和谐）的不完整季，本地与分享**各自独立判定**——谁不完整删谁，完整的那份正常进入画质对比。
- **库内多版本去重**：同一库内同一片 / 同一集存在多份 STRM（洗版、追更残留）时，只保留画质最优的一份，低版本联动删除腾空间。
- **多季保护**（关闭 / 开启 / 全量豁免）：本地多季合集时，仅当分享对全部季逐集达标才整体删本地；否则本地全季保护、不掏空合集。
- **洗版残留清理**：只识别本程序删除 STRM 后、附属文件删除失败形成的“已确认残留”，支持一键清理；普通 metadata-only / 空目录不会被猜测为残留。
- **入库进度**：影视探索 / 片库映射展示「已完整 / 连载中 X/Y / 未入库」及双库分库进度。
- **白名单 / 豁免**：按关键词跳过治理。
- **TMDB / Emby**：缺集、缺季检查与媒体库状态。
- **Telegram Bot**：远程查看状态并执行受保护的治理操作。
- **二次确认**：治理计划与实际删除分离。
- **CloudDrive2 联动**：可选；开启后本地 STRM 删除可同步处理对应云端源文件。

## 治理逻辑

### 画质比较（分层评分）

按优先级逐层比较，杜绝跨分辨率错判（如 1080p DV 误判高于 4K HDR）：

| 优先级 | 维度 | 说明 |
|---|---|---|
| 1 | 分辨率 | 2160p > 1080p > 720p > 其他 |
| 2 | HDR 维度 | DV > HDR10 > SDR |
| 3 | 编码档次 | REMUX > WEB-DL / 其他 |
| 4 | 帧率 | 60fps+ > 其他 |
| 5 | 色深 | 10bit > 8bit |

> 注意：**分辨率是第一优先级**。1080p Dolby Vision 不会被认为优于 4K HDR —— 只有当分辨率相同时，才继续比较 HDR、编码等维度。

### 决策模型（规则设置中切换）

| 策略 | 行为 |
|---|---|
| 画质优先（默认） | 两库比画质，高者胜出；平局按「平局保留本地」开关决定 |
| 保留本地 | 本地库永远优先，分享库只作补充 |
| 保留分享 | 分享库永远优先，节省 115 网盘空间 |

### 剧集治理（按季原子处理）

- **残次品独立判定**：本地、分享各自独立看「是否从 E01 起连续无断层」——前序缺失（缺 E01）或中间断层（疑似被和谐）的那一份判定为残次品删除，不做双库合并对照；完整的那一份正常进入画质对比。
- **逐集达标率择优**：两边都完整且集数对齐后，逐集比画质。**当分享画质达标的集数占比 ≥ 90%，且分享总集数不少于本地时**，删除本地、保留分享；否则淘汰分享、保留本地（单季只作用于单一库，不做跨库拆分）。
- **多季保护三档**：
  - 关闭：逐季独立择优。
  - 开启（默认）：分享对本地全部季逐集达标才整体删本地；否则本地全季保护（不掏空合集），仅清理分享中劣于本地的季副本。
  - 全量豁免：本地多季合集一律保护。

### 入库静默期

剧集 / 电影刚入库时常常只入了一部分。某个标题（含双库、所有季）的任一目录在 **15 分钟内**有新增或变动，就暂不进入治理队列（静默跳过，不出现在清单里），过了静默期再自然纳入；执行清理前的二次校验同样遵守。可在 `data/config.json` 里用 `ingest_quiet_minutes` 调整，`0` 表示关闭。

### 删除的安全机制

工具做了多层防误删，这也是它敢自动删文件的底气：

- **删除分级**：只有云端源文件被**精确匹配**（文件名完全一致，或标准化后唯一匹配）时才允许自动删除；出现多个候选、只能靠目录唯一兜底匹配、或根本找不到时，**一律保留 STRM 不动**。
- **删不动就不删**：云端源文件删除失败或超时，对应的 STRM 也会保留，绝不留下"指针还在、源没了"的坏记录。
- **附属文件连根拔**：删除 STRM 时，同名的 `-mediainfo.json`、`.nfo`、`.srt`、`.ass` 等附属文件一并清理，且**只匹配同名文件**，不会误伤同目录下其他集的字幕。
- **目录白名单**：库根目录、分类目录永不被自动删除；只有媒体专属目录参与清理。

## 快速开始（3 分钟）

### 运行要求

- Docker 20.10+ / Docker Compose v2+
- Linux / NAS 环境（x86_64 或 ARM64）
- 两个可读写的 STRM 媒体目录（本地库 + 分享库）
- 如需联动删除 CloudDrive2 源文件，另需提供对应挂载目录

### 1. 准备目录

```bash
mkdir -p /vol1/1000/docker/ttd-guard/data
cd /vol1/1000/docker/ttd-guard
```

### 2. 创建 `docker-compose.yml`

无需下载源码、无需自己 build，直接从 GHCR 拉预构建镜像。**只需要改三处**：

- `WEB_PASSWORD` → 改成你自己的强密码（**不设密码容器会拒绝启动**）
- `/你的本地影视库`、`/你的分享影视库` → 改成宿主机上的实际路径（**只改冒号左边**）
- 不用 CloudDrive2 联动就删掉 `/media/cloud` 那行，保持 `ENABLE_CD2_WATCHDOG: "0"`

```yaml
services:
  ttd-guard:
    image: ghcr.io/xcgtb/ttd-guard:latest
    container_name: ttd-guard
    restart: unless-stopped
    network_mode: host
    environment:
      TZ: Asia/Shanghai
      WEB_USER: admin
      WEB_PASSWORD: 请修改成自己的强密码   # ← 必改
      ENABLE_CD2_WATCHDOG: "0"           # ← 使用 CloudDrive2 联动时改 "1"
    volumes:
      - ./data:/data                                    # 配置与日志
      - /你的本地影视库:/media/local:rw                  # ← 必改
      - /你的分享影视库:/media/share:rw                   # ← 必改
      # 使用 CloudDrive2 联动时保留
      - /你的CloudDrive2影视库:/media/cloud:rslave      # ← 必改
```

> **安全提示：** `WEB_PASSWORD` 不要使用示例密码。真实密码只保存在你自己的 NAS `docker-compose.yml` / `.env` 中，**不要提交到 GitHub**。
>
> 冒号**右边**的容器内路径（`/data`、`/media/local`、`/media/share`、`/media/cloud`）是固定的，**不要修改**。

### 3. 启动并访问

```bash
docker compose pull
docker compose up -d
docker compose ps
```

浏览器打开：

```text
http://NAS-IP:8321
```

用 `WEB_USER` / `WEB_PASSWORD` 登录即可。第一次进去，建议先到「规则设置」填好 Emby 地址与 API Key、TMDB API Key。

### 4. 配置 Emby 路径映射

TTD Guard 靠 Emby 返回的文件路径判断一部片属于本地库还是分享库（片库映射、影视探索、单剧删除都依赖它）。请在「规则设置 → 服务配置」里填写 **Emby 中的本地库路径** / **Emby 中的分享库路径**，即 Emby 媒体库里看到的 STRM 根目录（Emby 容器内路径，不是 TTD Guard 的 `/media/local`）。不确定时点 Emby 的「测试连接」，结果里会列出 Emby 各媒体库的文件夹路径并标出哪些已对上。也可以用环境变量 `EMBY_LOCAL_PATH` / `EMBY_SHARE_PATH` 固定（会覆盖 Web 设置页的值）。默认值为 `/strm/115网盘/影视媒体库`、`/strm/115网盘/分享影视库`。

## Web 界面

同一套页面自适应手机与电脑：电脑端侧边栏常驻，手机端点左上角菜单展开；侧边栏共 8 个入口，相关功能合并为子页，页面顶部切换。

| 页面 | 作用 |
|---|---|
| 治理总览 | STRM 总量（网盘 / 分享占比）、剧集 / 总集数 / 电影统计、Emby 与 TMDB 状态；24H 入库、追更订阅、每日晨报、白名单一览；待处理（待删本地 / 待淘汰分享 / 受保护 / 白名单豁免）、剧集健康度、缺集最多；总库分类统计（可切换两库合计 / 本地库 / 分享库，**点击分类直接跳到片库映射并按该分类筛选**）；快速操作与策略快照 |
| 双库治理 | 子页：**清单**（扫描双库生成治理清单，确认后执行）、**洗版残留**（只扫描有删除血缘的已确认残留，一键清理） |
| 片库映射 | Emby 库总览，剧集 / 电影分库归类；海报墙**无限滚动**；吸顶工具条集成搜索、状态筛选（对齐 / 缺集 / 超集 / 在更 / 未匹配）与本地 / 分享范围切换；展示已入库集数与缺集 |
| 影视探索 | 浏览 TMDB 内容，展示「已完整 / 连载中 X/Y / 未入库」入库进度，可订阅追更 |
| 追更订阅 | 管理订阅，后台定期检查新集入库 / 缺集 |
| 每日简报 | 子页：**入库汇报**（近 24 小时入库统计）、**晨报推送**（定时推送到 Telegram，支持提前预热与预览） |
| 执行记录 | 子页：**执行日志**（治理 / 清理操作的审计日志）、**计划存档**（每次扫描的 Plan 历史，保留 7 天供审计） |
| 规则设置 | 分三组：**治理规则**（治理策略、特别篇策略、白名单）、**自动任务**（入库监控、双库定时巡检）、**服务连接**（Emby / TMDB / Telegram 配置与 Bot 状态）；电脑端左侧目录切换，手机端顶部标签切换，保存栏吸底 |

## 常见问题

**会误删我的文件吗？**
多层防护：只有精确匹配到云端源文件才会自动删；匹配存疑（多个候选 / 仅目录兜底 / 找不到）一律保留；云端删除失败则 STRM 也不删。删除前还有一次基于入库静默期的二次校验。并且所有操作都会写入审计日志，可在「执行记录」里回查。

**删掉的文件还能找回吗？**

**不能。所有删除都是立即且不可逆的——工具不保留副本、不提供回收站。**

- **STRM 文件**：直接删除。
- **云端 115 源文件**：同样直接删除，删掉的是网盘上的真实文件。
- **同名附属文件**：字幕 / nfo / mediainfo 一并删除。

所以**第一次部署务必只做预览**：先扫描出清单、不要点执行，确认清单完全符合预期后再正式清理。

**必须使用 115 网盘和 CloudDrive2 吗？**
不必须。核心的「双库比画质、比完整度」不依赖 CloudDrive2——只要你有两个 STRM 目录即可。CloudDrive2 联动只是额外的「删本地时顺便删云端源文件」能力，可以关闭。

**支持 Jellyfin / Plex 吗？**
目前媒体库状态、缺集检查是通过 **Emby API** 实现的。Jellyfin 的 API 与 Emby 高度相似，但未经官方验证；Plex 暂不支持。如果你只想要双库治理，不填 Emby 也能用。

**能不用 Docker 部署吗？**
可以，但需要自己准备 Python 3.11 环境、`pip install -r requirements.txt`，并把媒体目录挂到 `/media/local`、`/media/share`，然后运行 `uvicorn app.main:app`。Docker 是官方唯一推荐的部署方式。

**忘记 Web 密码了怎么办？**
修改 `docker-compose.yml` 里的 `WEB_PASSWORD`，然后 `docker compose up -d` 重启容器即可。登录会话 Cookie 有效期为 30 天。

**8321 端口被占用了？**
容器默认监听 8321（`network_mode: host`）。可在 `docker-compose.yml` 中覆盖 `command` 修改 uvicorn 端口，并同步设置 `PORT` 环境变量（供容器健康检查使用）。

**治理计划保留多久？**
每次扫描的计划保留 **7 天**，供事后审计。审计日志为 JSONL 格式，单文件超过 5MB 自动轮转，保留 3 份历史备份。
